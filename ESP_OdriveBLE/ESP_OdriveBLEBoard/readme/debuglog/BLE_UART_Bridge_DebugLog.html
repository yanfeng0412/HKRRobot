🔵 2026-05-14  —  BLE UART 透传初步实现 + 稳定性问题首次暴露 Day 1 ▶
📋 需求确认：BLE ↔ UART0 双向透传
当前状态：BLE 已能正常连接，但手机发送的数据不打印到 TXD0/RXD0； TXD0/RXD0 收到任何数据也不透传到 BLE。
目标：GPIO43=TXD0，GPIO44=RXD0 与 BLE NUS 双向无缝透传。
✅ 实现 BLE→UART0（TXD0）方向
修改 on_ble_rx() 回调：由原先的追加\n后转发给 ODrive， 改为直接调用 uart_write_bytes(UART_NUM_0, data, len)。
✅ 实现 UART0（RXD0）→BLE 方向
新增 uart0_to_ble_task()：持续调用 uart_read_bytes(UART_NUM_0, buf, 512, 20ms)， 有连接时转发给 ble_uart_send()。
安装 UART0 驱动：uart_driver_install(UART_NUM_0, 2048, 0, 0, NULL, 0)。
⚠️ 问题：BLE 同时收发时断连，板子重启
现象：ODrive 静止每秒发一次状态帧，转轮时最高 10ms 一帧； 只要串口收到数据 BLE 就断开，整板重启。
怀疑方向：RTOS 栈溢出 / NimBLE 状态机被阻塞。
✅ Fix 1：UART0 TX buf=0 阻塞 NimBLE 宿主任务
根因：on_ble_rx 在 NimBLE 宿主任务内执行， uart_driver_install(..., TX_buf=0, ...) 导致 uart_write_bytes 等待字节物理发完才返回， 卡住 NimBLE 宿主任务无法处理 BLE 心跳 → 断连。
修复：TX buf 改为 2048，写操作立即返回。
✅ Fix 2：桥接任务栈溢出
根因：uart0_to_ble_task 栈仅 2048 字节， 而局部 uint8_t buf[512] + FreeRTOS 开销 + 调用帧超出栈上限 → 随机崩溃重启。
修复：buf 改为 static（存放在 BSS，不占任务栈），任务栈扩至 4096。
✅ Fix 3：ble_uart_send 无背压死循环
原逻辑：固定 20 字节分片死循环发送，NimBLE mbuf 池耗尽时直接 return ERR， 但调用方无感知、任务继续塞数据 → 队列爆炸 → 断连。
修复：遇到 BLE_HS_EBUSY / BLE_HS_ENOMEM 时 等 15ms（一个连接间隔）再重试，最多 5 次；不可恢复错误丢包退出。
✅ BLE 连接质量优化：MTU 协商 + 连接间隔
连接成功时调用 ble_att_set_preferred_mtu(250)， 待手机发起 MTU 交换后 BLE_GAP_EVENT_MTU 回调更新 s_max_payload = MTU - 3； 100 字节数据从 5 片降至 1 片。
同时请求连接间隔 10–20ms（itvl 8–16），适配 ODrive 10ms 上报节奏。
⚠️ 日志噪声问题：SERVO/LCD/Touch 日志污染透传通道
现象：BLE 收到端看到大量 SERVO moving、LCD_Fill、I2C 通信失败等无关日志， 这些来自仍在运行的舵机随机运动任务、ODrive LCD 刷新任务、触摸屏测试。
根本原因：esp_log_level_set("*", ESP_LOG_WARN) 只压制 ESP_LOG 宏，无法屏蔽 printf()。
✅ 禁用所有非透传模块
注释掉：servo_start_random_motion()、 xTaskCreate(odrive_lcd_task)、 触摸屏测试循环、RGB565_DualModeInteractive()、 LCD_Init()。 清理全部 printf 的 Idle/LCD 完成提示。
🟢 2026-05-15  —  重启根因定位 + 三大编译错误修复 + 构建成功 Day 2 ▶
🔴 重启根因 1：NVS 未初始化 → BLE 射频校准失败
日志：E (460) phy_init: esp_phy_load_cal_data_from_nvs: NVS has not been initialized.
NVS 未初始化时 BLE 协议栈无法读取射频校准数据，运行在降级模式， 高负载（UART 高频数据）时极易触发内部断言重启。
修复：app_main 最顶部（BLE init 之前）添加 nvs_flash_init()，含 erase 重试逻辑。
🔴 重启根因 2：UART0 双重 ISR 冲突 → panic
根因：ESP-IDF 启动时控制台使用 ROM 内置 UART0 ISR； 再次调用 uart_driver_install(UART_NUM_0, ...) 会安装第二个 ISR，两个 ISR 同时响应同一 RX 中断 → 内存踩踏 / 断言失败 → 重启。
修复：安装驱动后调用 uart_vfs_dev_use_driver(0) （头文件 driver/uart_vfs.h），让 VFS 层切换到新驱动，ROM ISR 被卸载。
🔴 编译错误 1：BLE_HS_ENOBUFS 未定义
错误信息：error: 'BLE_HS_ENOBUFS' undeclared; did you mean 'BLE_HS_ENOMEM'?
原因：该符号在此版本 NimBLE 中不存在，BLE_HS_ENOMEM 已覆盖所有内存/缓冲耗尽情况。
修复：将条件合并为 BLE_HS_EBUSY || BLE_HS_ENOMEM。
🔴 编译错误 2：GCC ICE — esp_lcd_panel_rgb.c Segfault
错误信息：internal compiler error: Segmentation fault during RTL pass: ira
GCC 在处理 rgb_panel_draw_bitmap 时， IRA（寄存器分配）pass 本身崩溃，这是编译器 bug，与项目代码无关。
修复：在根 CMakeLists.txt 添加： target_compile_options(__idf_esp_lcd PRIVATE -O1)， 单独降低 esp_lcd 组件优化级别绕过触发路径。
🔴 链接错误：ble_gattc_exchange_mtu 未定义
错误信息：undefined reference to 'ble_gattc_exchange_mtu'
原因：该函数属于 GATT Client 侧 API， 需要 CONFIG_BT_NIMBLE_ROLE_CENTRAL； 本项目是外设端（Server），未编译 GATT Client。
修复：删除 ble_gattc_exchange_mtu() 调用， 仅保留 ble_att_set_preferred_mtu(250)。 手机作为 Central 会主动发起 MTU 交换，ESP32 用首选值响应，效果相同。
✅ 构建成功 — P169H002.bin 生成
Binary size: 0x7dc40 bytes，占最小 app 分区的 16%， 剩余 84% flash 空间。

🐛 Bug 根因分析详情
BUG #1 BLE 收到数据时断连 — NimBLE 宿主任务被阻塞 main.c → on_ble_rx()

症状：手机发送数据后 BLE 立即断开。
根因：GATT 写入回调 on_ble_rx 在 NimBLE 宿主任务上下文内同步执行。 UART0 的 TX 缓冲区大小为 0，uart_write_bytes 会忙等到字节物理从 GPIO43 发完才返回（对于 115200 baud 一字节 ≈ 87μs）。 在这段时间内 NimBLE 宿主任务无法处理 LL ACK / L2CAP / ATT，超时后 Controller 触发断连。

❌ 修复前
uart_driver_install(UART_NUM_0, 2048, 0, // TX buf = 0 0, NULL, 0);
✅ 修复后
uart_driver_install(UART_NUM_0, 4096, 2048, // TX buf = 2048 0, NULL, 0);
BUG #2 任务栈溢出导致随机崩溃重启 main.c → uart0_to_ble_task()

症状：运行一段时间后随机重启，backtrace 指向任务栈区域。
根因：任务栈仅 2048 字节，但局部变量 uint8_t buf[512] 独占 512 字节， 加上 FreeRTOS TCB 开销、函数调用帧（寄存器保存 ~200B）以及 ble_uart_send 的内部栈帧， 实际需求超出 2048 字节。

❌ 修复前
static void uart0_to_ble_task(void *arg) { uint8_t buf[512]; // 占用任务栈! ... } // 创建时: xTaskCreate(..., 2048, ...);
✅ 修复后
static void uart0_to_ble_task(void *arg) { static uint8_t buf[512]; // 存 BSS ... } // 创建时: xTaskCreate(..., 4096, ...);
BUG #3 NVS 未初始化 → BLE 射频校准失败 main.c → app_main()

症状：日志出现 E phy_init: esp_phy_load_cal_data_from_nvs: NVS has not been initialized， BLE 在高负载下不稳定。
根因：nvs_flash_init() 未在 BLE 初始化前调用。 NVS 用于存储 BLE 射频校准数据和配对绑定信息，缺少时协议栈退化为默认参数运行， 同时频繁触发 WARNING 级 log 占用时间片。

// app_main 最顶部，BLE init 之前 esp_err_t nvs_ret = nvs_flash_init(); if (nvs_ret == ESP_ERR_NVS_NO_FREE_PAGES || nvs_ret == ESP_ERR_NVS_NEW_VERSION_FOUND) { nvs_flash_erase(); nvs_flash_init(); }
BUG #4 UART0 双重 ISR → 收到数据时 panic 重启 main.c → app_main()

症状：只要 RXD0 收到任何字节，板子立即重启。
根因：ESP-IDF ROM 初始化时已为 UART0 挂载了控制台 ISR（用于 printf）。 再次调用 uart_driver_install(UART_NUM_0, ...) 会额外挂载驱动 ISR， 两个 ISR 同时响应 UART0_INTR → 争夺 FIFO 读指针 → 数据损坏 / 断言失败 → 重启。

uart_driver_install(UART_NUM_0, 4096, 2048, 0, NULL, 0); // 卸载 ROM ISR，VFS 层改走驱动接口 uart_vfs_dev_use_driver(0); // driver/uart_vfs.h
BUG #5 GCC ICE：esp_lcd_panel_rgb.c 编译器内部崩溃 CMakeLists.txt

错误：internal compiler error: Segmentation fault during RTL pass: ira
GCC (xtensa-esp32s3-elf) 在 IRA（寄存器分配）pass 处理 rgb_panel_draw_bitmap 时自身崩溃，属于编译器 bug，不是代码问题。
解决：对 esp_lcd 组件单独指定 -O1，绕过触发路径。

# CMakeLists.txt 末尾追加 target_compile_options(__idf_esp_lcd PRIVATE -O1)
BUG #6 链接错误：ble_gattc_exchange_mtu 未定义 ble_uart.c → ble_uart_gap_event()

错误：undefined reference to 'ble_gattc_exchange_mtu'
原因：该函数属于 GATT Client 角色，需要开启 CONFIG_BT_NIMBLE_ROLE_CENTRAL； 本项目只作为外设端（Peripheral/Server），未编译该模块。
修复：删除主动发起 MTU 交换的调用，仅设置首选值；手机 Central 端会主动发起，效果等同。

❌ 修复前
ble_att_set_preferred_mtu(250); ble_gattc_exchange_mtu(s_conn_handle, NULL, NULL);
✅ 修复后
ble_att_set_preferred_mtu(250); // 手机 Central 端主动发起 MTU 交换 // BLE_GAP_EVENT_MTU 回调更新 s_max_payload
BUG #7 编译错误：BLE_HS_ENOBUFS 未声明 ble_uart.c → ble_uart_send()

错误：error: 'BLE_HS_ENOBUFS' undeclared; did you mean 'BLE_HS_ENOMEM'?
该符号在 IDF v5.5.4 的 NimBLE 版本中不存在，BLE_HS_ENOMEM 已包含所有内存/缓冲耗尽场景。

❌ 修复前
if (rc == BLE_HS_EBUSY || rc == BLE_HS_ENOMEM || rc == BLE_HS_ENOBUFS) {
✅ 修复后
if (rc == BLE_HS_EBUSY || rc == BLE_HS_ENOMEM) {
