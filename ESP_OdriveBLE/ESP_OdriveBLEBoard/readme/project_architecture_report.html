ESP32-S3 HKR Robot Middleware

Project P169H002 · ESP-IDF Framework · Generated 2026-05-13

System Architecture Summary

The HKR Robot Middleware is an ESP32-S3 based embedded system that bridges a mobile phone (BLE), an ODrive motor controller (UART), and various peripherals (LCD touch display, servo motor, audio codec). It also integrates cloud AI services via Dify Chat API and Google Cloud TTS/SST.

Servo Control Architecture

servo_init() → ledc_timer_config
50Hz, 14-bit → ledc_channel_config
GPIO41, duty=90° → Ready
current_angle=90°
servo_set_angle(θ) — Immediate
Clamp θ
[0, 180] → angle_to_duty()
pulse = 500 + θ/180*2000 µs
duty = pulse/20000 * 16383 → ledc_set_duty()
+ update
servo_move_smooth(θ, t_ms) — S-Curve
|Δθ|<0.5°?
→ direct set → steps = t_ms/20ms
for i=0..steps: → cubic_spline(t)
t = i/steps
3t² - 2t³ (S-curve) → angle = start
+ diff * interp → servo_set_angle()
servo_random_motion_task — Background Loop
Random target
30°-150° → Random duration
1000-2500ms → servo_move_smooth() → Random pause
500-2000ms → vTaskDelay(pause) → Loop forever
Cubic Spline Formula: f(t) = 3t² - 2t³ where t ∈ [0,1]. This S-curve provides zero velocity at start/end points with smooth acceleration in between. The task runs at priority 1 (lowest) to avoid preempting UI and communication tasks.

Memory Map Notes

Flash

  • Total: 8 MB (typical ESP32-S3-WROOM)
  • Used by partitions: ~3.06 MB
  • Available for OTA/SPIFFS: ~5 MB
  • Embedded JPEG images in app binary
  • RGB565 arrays compiled into firmware

PSRAM (SPIRAM)

  • Used by Dify module for TLS (mbedTLS)
  • force_mbedtls_use_psram() redirects alloc
  • 96KB warm-up allocation at Dify init
  • LCD SPI max_transfer_sz = full screen (136KB)

RTOS Heap Usage

  • odrive_rx: 4096 stack (UART RX loop)
  • dify_worker: 8192 stack (HTTP + TLS)
  • servo_random: 4096 stack (smooth motion)
  • sst_capture: 4096 stack (audio processing)
  • LCD Fill: malloc(512) per fill call
  • Dify HTTP: 4KB response buffer (static)
