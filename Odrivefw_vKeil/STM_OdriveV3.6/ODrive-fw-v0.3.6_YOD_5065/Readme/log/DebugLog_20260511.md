# ODrive v0.3.6 调试记录 — 2026-05-11

**目标：** 5065 无刷电机，无传感器 FOC，USART2 单线控制终端（心跳 TX + 命令 RX + 回复 TX）

---

## 问题一：vbus 读数错误（13.7V，实为 24V）

**现象：** 心跳打印 `vbus=13.7`，实际供电 24V。  
**根本原因：** `main.h` 中 `HW_VERSION_VOLTAGE=24`，导致分压比 `VBUS_S_DIVIDER_RATIO=11.0f`（11:1）。  
但板子实际为 v3.4 硬件，分压比是 19:1，对应 `HW_VERSION_VOLTAGE=48`。  
**解决方案：**
```c
// Firmware/Inc/main.h
#define HW_VERSION_VOLTAGE 48   // 修改前为 24
```
修改后 `VBUS_S_DIVIDER_RATIO=19.0f`，vbus 读数恢复正确（~23.6V）。

## 问题二：HAL Lock Bug — USART2 TX 被 RX 阻塞（始终返回 HAL_BUSY）

**现象：** 调用 `HAL_UART_Transmit(&huart2, ...)` 无输出，无报错，直接 return。  
**根本原因：**  
`HAL_UART_Receive()` 带超时版本，超时返回时不清除 `RxState=BUSY_RX`（HAL 库 bug）。  
之后 `HAL_UART_Transmit()` 检查 `RxState != READY` → 返回 `HAL_BUSY`，TX 永远失败。  
**解决方案：** 放弃 `HAL_UART_Receive()`，改用 **中断 + 环形缓冲区** 接收：

```c
// usart.c — MspInit 末尾开启 RXNE 中断
__HAL_UART_ENABLE_IT(&huart2, UART_IT_RXNE);
HAL_NVIC_SetPriority(USART2_IRQn, 6, 0);
HAL_NVIC_EnableIRQ(USART2_IRQn);

// stm32f4xx_it.c — USART2_IRQHandler
void USART2_IRQHandler(void) {
    uint32_t sr = USART2->SR;
    if (sr & USART_SR_RXNE) {
        uint8_t byte = (uint8_t)(USART2->DR & 0xFF);
        uint32_t next = (uart2_rx_head + 1) % UART2_RX_BUF_SIZE;
        if (next != uart2_rx_tail)
            uart2_rx_buf[uart2_rx_head] = byte;
        uart2_rx_head = next;
    }
    if (sr & USART_SR_ORE) { (void)USART2->DR; }  // 清除溢出
}
```
TX 仍使用 `HAL_UART_Transmit()`（阻塞），因为不再碰 RxState，无冲突。

## 问题三：USART2 PA2 与 EXTI2 冲突（第一次 USART2 初始化后通信失败）

**现象：** `MX_USART2_Init()` 调用后 TX 时好时坏，复位后 EXTI2 中断干扰。  
**根本原因：** 板子原始配置 PA2 为 `GPIO_3`（外部中断 EXTI2_IRQn），与 USART2_TX 复用冲突。  
**解决方案：** 初始化 USART2 前先禁用 EXTI2：
```c
void MX_USART2_Init(void) {
    HAL_NVIC_DisableIRQ(EXTI2_IRQn);  // 先禁 EXTI2，避免 PA2 冲突
    // ... GPIO AF7 配置 + UART 初始化 ...
}
```

## 问题四：堆栈溢出（uart2_test_thread 崩溃）

**现象：** USART2 线程开启 RX+命令解析后，固件随机死机或无输出。  
**根本原因：** 线程栈设为 256 words，`snprintf` + `motor_parse_cmd` 调用深度超出。  
**解决方案：**
```c
// freertos.c
osThreadDef(task_uart2_test, uart2_test_thread, osPriorityLow, 0, 512);
//                                                                   ^^^
// 从 256 改为 512 words
```
同时启用堆栈溢出检测：
```c
// FreeRTOSConfig.h
#define configCHECK_FOR_STACK_OVERFLOW 2
```

## 问题五：err0=23（ERROR_DC_BUS_BROWNOUT）校准时触发

**现象：** 上电校准阶段 vbus 骤降至 <8V，触发 brownout，校准失败。  
**根本原因：** 校准电流设为 10A，实验室电源限流 10A → 校准脉冲把电源压垮。  
**解决方案：**
```c
// app_config.h (MOTOR_CONFIG==2)
#define APP_CALIBRATION_CURRENT   3.0f   // 从 10A 降至 3A
#define APP_RESISTANCE_CALIB_MAXV 2.0f   // 相应调低
```

## 问题六：err0=23（ERROR_DC_BUS_BROWNOUT）开环启动时触发

**现象：** 校准成功后，spin-up 阶段 vbus 骤降，err0=23。  
**根本原因：** 开环启动电流 10A + 加速度 300 rad/s² 过大，电源限流导致 vbus 崩溃。  
**解决方案：**
```c
// app_config.h (MOTOR_CONFIG==2)
#define APP_SPIN_UP_CURRENT       6.0f    // 从 10A → 6A
#define APP_SPIN_UP_ACCELERATION  50.0f   // 从 300 → 50 rad/s²
#define APP_SPIN_UP_TARGET_VEL    250.0f  // 从 300 → 250 rad/s（切换时反电势更强）
```

## 问题七：`$M0,H,0;` 发送后电机不立即停止，随后 err0=23

**现象：** 发送 H 命令，电机速度不变，随后 vbus 从 23.5V → 7.3V → 5.3V → err0=23。  
**根本原因：** H 命令原实现仅调 `set_vel_setpoint(mot, 0, 0)`。  
速度环 PI 积分器发现 `vel_error = 0 - actual_vel`（负值）→ 产生大制动电流 → 高速下制动电流远超供电能力 → vbus 崩溃。  
**解决方案：** H 命令直接禁用电机控制（PWM 立即关断，转子惯性滑行停止）：
```c
// commands.c — case 'H':
case 'H': {
    mot->enable_control   = false;   // ← 立即关 PWM，不再产生制动电流
    mot->vel_setpoint     = 0.0f;
    mot->current_setpoint = 0.0f;
    cmd_printf("[%s,H,...]\n", ...);
    break;
}
```

## 问题八：`$M0,H,0;` 后再发 `$M0,V,5.0;` 电机不运行（Case 1）

**现象：** H 停止后，直接发 V 命令无响应（不重新启动）。  
**根本原因：** `motor_thread` 进入控制循环的条件是 `calibration_ok && enable_control`。  
H 命令设了 `enable_control=false`，V 命令只调 `set_vel_setpoint()`，不改 `enable_control`，故条件不满足。  
**错误的临时办法：** 用 `$M0,E,0;` 重新触发校准（浪费 2–3 秒，且实际上不需要）。  
**正确解决方案：** V 命令检测到"已校准但被 H 停止"状态时，直接重新使能：
```c
// commands.c — case 'V':
if (mot->calibration_ok && !mot->enable_control) {
    mot->enable_control = true;  // 跳过重新校准，直接恢复 spin-up
}
set_vel_setpoint(mot, vel_rad_s, 0.0f);
```
效果：H → V 约 1 秒后电机恢复（仅重新 spin-up，不重新测 R/L）。

## 问题九：`$M0,V,5.0;` 有时堵转，电流从 0.1A 累加到 1A

**现象：** 有时电机正常转，有时听到电流声且速度不动，电流持续增大。  
**根本原因：** `spin_up_sensorless()` 是纯开环过程，用固定相位速率推电流。  
若转子未能跟上旋转磁场（脱步），进入闭环后观测器位置估算错误，电流 PI 积分器累积 → 电流持续增大。  
触发原因：启动电流偏低（4A）、加速太快（80 rad/s²）、切换点反电势太弱（150 rad/s）。  
**解决方案：**
```c
// app_config.h (MOTOR_CONFIG==2)
#define APP_SPIN_UP_CURRENT       6.0f    // 4A → 6A，增大拖动力矩
#define APP_SPIN_UP_ACCELERATION  50.0f   // 80 → 50 rad/s²，更慢让转子跟上
#define APP_SPIN_UP_TARGET_VEL    250.0f  // 150 → 250 rad/s，切换时反电势翻倍
```

## 命令协议说明（USART2，115200 8N1）

| 发送命令 | 含义 | 示例 |
|---------|------|------|
| `$M0,V,x;` | 设速度（km/h），`APP_WHEEL_RADIUS_M=0.025` 时转换 km/h→rad/s | `$M0,V,5.0;` ≈ 55 rad/s |
| `$M0,H,0;` | 立即停止（PWM 关断，惯性滑行） | — |
| `$M0,Q,0;` | 查询当前状态 | — |
| `$M0,E,0;` | 清除错误 + 重新校准 + 使能 | err≠0 时使用 |
| `$M0,I,x;` | 直接设电流（A） | `$M0,I,2.0;` |
| `$M0,T,x;` | 设扭矩（N·m），转换为电流 | `$M0,T,0.5;` |

**回复格式：** `[M0,<mode>,<vel_rad/s>,<pos_deg>,<Iq_A>,<Vbus_V>,<err>]`  
**心跳格式（1秒）：** `[HB] cnt=N  vbus=X.X  vel0=X.X  Iq0=X.X  err0=N  calib=N  R=X.XXXX`

## 正常启动流程

```
上电 → motor_thread 自动运行 motor_calibration()（~3秒，测量 R/L）
    → 校准成功：心跳显示 calib=1，err0=0
    → spin_up_sensorless()：开环加速至 250 rad/s（约 5 秒）
    → control_motor_loop()：闭环速度控制
    → 发送 $M0,V,5.0; 设定目标速度
```

---

## 注意事项

- 不要在电机运行中发送 `$M0,E,0;`（会强制 `calibration_ok=false`，电机中途断开控制）
- H 停止后，V 命令可直接重启（跳过重新校准）
- E 命令用于 `err0≠0` 的故障恢复
- `vel0` 心跳值为电角速度 rad/s（电气角），机械转速 RPM = `vel0 / pole_pairs * 60 / (2π)`
- 供电建议：24V 实验室电源，限流 ≥ 8A（校准 3A + spin-up 6A + 余量）
