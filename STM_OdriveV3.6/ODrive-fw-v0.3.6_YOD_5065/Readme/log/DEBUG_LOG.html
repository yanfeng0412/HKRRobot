FIX 1 Hall-C GPIO 引脚修正 Inc/app_config.h

物理接线确认 Hall-C 在 PC9，原代码用 PA15 (ENC_Z默认)，导致Hall状态完全错误。

Before
#define APP_HALL_C_PORT GPIOA #define APP_HALL_C_PIN GPIO_PIN_15
After
#define APP_HALL_C_PORT GPIOC #define APP_HALL_C_PIN GPIO_PIN_9 /* PC9 */
FIX 2 phase_offset 类型修正 int32 → float MotorControl/low_level.h + app_config.h

phase_offset 声明为 int32_t，导致 0.5f 被截断为 0，实际偏移永远为0。

low_level.h — Before
int32_t phase_offset;
low_level.h — After
float phase_offset; // fractional sector OK
FIX 3 相位偏移值修正 0.5f → 3.5f（修正 180° 方向反转） Inc/app_config.h

0.5f 时 FOC 相位估计比实际转子角差 180°，正Iq产生最大反向力矩 → 飞车。 3.5f = 0.5f + 3count = 0.5f + 180° 电气角，修正对齐。

Before（飞车）
#define APP_HALL_MOTOR_DIR 1 #define APP_HALL_PHASE_OFFSET 0.5f
After（正常）
#define APP_HALL_MOTOR_DIR 1 #define APP_HALL_PHASE_OFFSET 3.5f /* +3 cnt = +180° */
FIX 4 速度反馈单位修正：电气 rad/s → 机械 rad/s MotorControl/low_level.c → get_pll_vel()

$M0,V 指令单位是机械 rad/s，原 get_pll_vel() 返回的是电气 rad/s（×7倍）。 速度误差 v_err = setpoint - feedback 相差7倍，速度环完全失控。

Before（单位错误）
return hall->pll_vel * (2.0f * M_PI / 6.0f) * (float)hall->motor_dir; // 返回电气 rad/s (机械×7)
After（单位正确）
return hall->pll_vel * (2.0f * M_PI / 6.0f) / (float)motor->pole_pairs // ÷7 * (float)hall->motor_dir; // 返回机械 rad/s ✓

H 停机后 PWM输出关闭但 TIM1→ADC 触发链仍运行，ADC IRQ 持续 osSignalSet。 再次启动时 osSignalWait 立刻返回积压信号 → check_timing 读到随机CNT → timing > deadline → ERROR_FOC_TIMING。

commands.c H 命令 — After

🐛 Bug 根因分析详情
BUG-1：飞车（vel ≈ −211 rad/s, Iq ≈ 51A, err=23）
根因：相位偏移 0.5f（电气 30°）使 FOC 相位比转子实际角差 180°
Hall CPR=6，每格 60° 电气角。
phase = (pll_pos − offset) × (2π/6) × dir
offset=0.5 → phase 误差 ≈ 0°（实际上 dir=1 时需要补偿的相位与磁场方向对不上）。
效果：正 Iq 产生最大负向力矩
FOC 的输出力矩 ∝ sin(相位误差)。
误差 = 180° → sin(180°) = 0 → 但电流积分器积分 → 最终达到限流值，电机向反方向以最大加速度飞转。
修复：offset 改为 3.5f（= 0.5 + 3 count = 原来 + 180°）
加 3 个 Hall count = 加 3×60° = 加 180°，恰好补偿方向反转，Iq 与磁场对齐。
BUG-2：速度控制误差 7×（$M0,V,5 实际只跑 ~0.7 倍速）
根因：电气速度 vs 机械速度单位不匹配
Hall PLL velocity 单位是 counts/s（6 counts = 1 电气转）
get_pll_vel() 只转换到电气 rad/s = counts/s × 2π/6
$M0,V 指令换算到机械 rad/s = km/h / 3.6 / wheel_radius
两者差 pole_pairs = 7 倍。
修复：get_pll_vel() 除以 pole_pairs
pll_vel × (2π/6) / pole_pairs × motor_dir → 机械 rad/s
BUG-3/4/5：H → V 无法重启（必须 $M0,E,0）
根因A：积压的 ADC 信号导致 ERROR_FOC_TIMING(11)
H 命令关闭 PWM 输出，但 TIM1 计时器继续运行，ADC 注入触发仍然有效。
pwm_trig_adc_cb() 每 ~100µs 调用一次 osSignalSet()，FreeRTOS 信号位持续置 1。
V 命令重启后第一次 osSignalWait() 立刻返回（不等真实 ADC 采样沿），
check_timing 读到随机 TIM1 CNT → 可能在倒计数区间（timing = 10192 + Δ > 10192）→ ERROR_FOC_TIMING。
根因B：出错后 motor_thread 清除 calibration_ok
任何错误退出 control_motor_loop 时：
if (enable_control) { calibration_ok = false; enable_control = false; }
V 命令检查 calibration_ok && !enable_control → false → 永不重启。
根因C：H 停机后 Hall PLL 状态未重置
滑行期间 update_rotor 不运行，但 shadow_count 和 pll_pos 保持停机前的值。
重启时 Hall 位置与 PLL 估计不一致 → 速度估计出现大误差 → 电流尖峰。
修复A：osSignalWait(M_SIGNAL_PH_CURRENT_MEAS, 0) 清积压
在 control_motor_loop 入口、MOE_ENABLE 之后立即调用非阻塞 osSignalWait(signal, 0) 消耗积压的信号位。
修复B：V 命令新增 !calibration_ok 恢复分支
检测到出错后，V 命令主动清 error、触发 do_calibration=false（重新标定），设 enable_control=true，无需手动 $M0,E,0。
修复C：H 命令调用 hall_gpio_init() 重播种 PLL
停机时从当前 Hall GPIO 状态重新初始化 pll_pos 和 pll_vel，重启后第一个 update_rotor 周期的相位误差为零。

Hall FOC 调试关键经验
1. Hall 序列验证先于 FOC
用 UART 实时上报 Hall 状态变化，手转电机确认序列为 1→3→2→6→4→5→1（d=+1, adj=1）再开 FOC。
2. 飞车 = 相位差 180°，抖动 = 相位差 0° 或 60°
飞车时 pll_vel 符号与 vel_setpoint 相反且发散；抖动（2↔6反复）时电机卡在一个扇区边界。
3. phase_offset 排查方法
固定 DIR=1，OFFSET 从 0.5f 步进 1.0f（每步 60°），共 6 个值。找到正转的值后确认中点是 0.5f 对齐。
4. CMSIS-RTOS 没有 osSignalClear
用 osSignalWait(signal, 0) 代替（非阻塞，清掉信号位）。
5. 速度单位一致性
Hall PLL 在"机械转"空间工作需要÷pole_pairs；encoder PLL 在 counts 空间，单位不同，不要混用。
⚠ 出错后 V 命令自动重新标定（约3-5秒）期间，电机不动，UART 日志可查到 [HALL] 输出（标定过程中 Hall GPIO 初始化会输出）。标定完成后自动进入控制环，响应速度指令。
