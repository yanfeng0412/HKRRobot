① 双命令同帧解析（Multi-command UART frame）
问题：同时发送 $M0,V,5.0;$M1,V,5.0;，板子只响应 M0，M1 丢失或延迟。
根因：原解析器仅识别 \r/\n/! 为帧结束符，; 当普通字符存入 buffer；sscanf 只解析第一条命令，剩余内容丢弃。
修复：把 ; 也作为帧结束符，处理后 不退出 while 循环，继续消耗 DMA buffer 中的后续字节。
// commands.c – cmd_parse_thread, inner while loop - if (c == '\r' || c == '\n' || c == '!') { - parse_buffer[parse_buffer_idx-1] = '\0'; - motor_parse_cmd(...); - reset_read_state = true; - break; + if (c == ';') { + // 处理当前命令，重置 parse_state，但不 break + // → 同一 DMA 帧里的下一条命令继续被解析 + motor_parse_cmd(...); parse_buffer_idx = 0; read_active = false; + } else if (c == '\r' || c == '\n' || c == '!') { + motor_parse_cmd(...); reset_read_state = true; break;
支持的发送格式：
$M0,V,5.0;$M1,V,5.0; ← 两条命令同帧，均执行
$M0,H,0;$M1,H,0;$M0,V,3.0; ← 三条命令，均执行
旧格式 $M0,V,5.0\n 继续有效

② 积分增益回调降噪
问题：电机运行时出现轻微抖动（前两版没有）。
根因：上次将 vel_gain 从 0.01 提升到 0.02，Hall CPR=6 每个 sector 边沿触发一次 pll_vel 修正脉冲，高积分增益放大 6 velocity samples/rev 的量化噪声。
修复：积分增益从 0.04 调回 0.01，P 项（0.02）仍提供充足动态响应。
- #define APP_VEL_INTEGRATOR_GAIN 0.04f // [A/(rad/s·s)] + #define APP_VEL_INTEGRATOR_GAIN 0.01f // reduced: CPR=6 量化噪声抑制

③ M0 方向反转（正确方式）
问题：M0 电机运转方向与预期相反。
错误尝试：将 APP_HALL_MOTOR_DIR 从 1 改为 -1 → M0 出现剧烈抖动+噪声，M1 正常。
根因分析：
motor_dir 是 FOC 校准参数，同时影响两处：
• hall_phase_from_pos()：phase = (2π/6)×(pos−3.5)×motor_dir 定子磁场角度
• get_pll_vel()：速度反馈符号

phase_offset=3.5 是针对 motor_dir=1 校准的。改成 -1 后相位角约偏移 120°~180°， FOC 磁场方向错误 → 抖动噪声。绝不能通过修改 motor_dir 来反转应用层方向。
正确修复：在指令层（commands.c V handler）做符号翻转，FOC 校准参数不动。
// app_config.h - #define APP_HALL_MOTOR_DIR -1 // 错误：破坏 FOC 校准 + #define APP_HALL_MOTOR_DIR 1 // FOC 校准值，勿动 + #define APP_M0_VEL_DIRECTION (-1) // 应用层：M0 输出方向取反 + #define APP_M1_VEL_DIRECTION 1 // 应用层：M1 正向 // commands.c – V handler + static const int8_t app_dir[2] = { APP_M0_VEL_DIRECTION, APP_M1_VEL_DIRECTION }; + vel_rad_s *= (float)app_dir[motor_idx]; // 指令层翻转，不影响 FOC
结论：M0 输出方向翻转成功，FOC 校准不受影响，M0/M1 均无噪声。 如需再次翻转方向，只需修改 APP_M0_VEL_DIRECTION（值 1 或 -1）。

④ M1 启动慢 → 主动制动 H 命令修复
问题A（启动慢）："前面不动→开始缓慢加速"，M0 实时响应而 M1 不行。
根因：vel_gain=0.01 在 5 km/h 误差下 P 项仅 0.556 A，低于 5065 静摩擦；积分器旧值 0.002 需 13 秒才能达 2A。
问题B（H 命令）："减速有时停有时变慢转速"。根因：H 直接切 PWM，空载电机自由滑行数秒。
修复项旧值新值效果
vel_gain0.010.02P 项 1.11A，立即启动
vel_integrator_gain0.0020.04→0.010.4 s 达 2A，再调低噪声
APP_HALL_STARTUP_CURRENT—2.0 A启动前馈，第一个 FOC 周期即可克服静摩擦
H 命令enable_control=false（自由滑行）vel_setpoint=0 + 4096 tick 主动制动500 ms 内主动减速停止
V 命令—halt_timeout=-1 取消制动H 后立即 V 可即时响应

① M1 Hall GPIO 引脚重映射
M1 原 Hall-C 用 PB3（ENC_Z），与 SWO 复用冲突。改为 PC15（M1_DC_CAL 复用为输入）。
// main.h - #define M1_ENC_Z_Pin GPIO_PIN_3 - #define M1_ENC_Z_GPIO_Port GPIOB + #define M1_ENC_Z_Pin GPIO_PIN_15 + #define M1_ENC_Z_GPIO_Port GPIOC
注意：PC15 与 M0_ENC_Z（PC9）共享 EXTI15_10 中断线。 Hall 检测不依赖 EXTI（轮询模式），因此不影响功能。

① ERROR_PHASE_RESISTANCE_TIMING 修复
问题：重新校准时报 timing error，第一次校准成功，第二次概率性失败。
根因：motor_thread 进入 motor_calibration() 时，M_SIGNAL_PH_CURRENT_MEAS 信号位已被 ADC IRQ 置位（PWM 关闭期间 ADC 仍触发）。osSignalWait() 立即返回， 此时 TIM8 处于下计数阶段，check_timing 读到 CNT > 1.5×PERIOD → 超时报错。
// motor_thread – 校准前 + osSignalWait(M_SIGNAL_PH_CURRENT_MEAS, 0); // drain 残留信号 motor_calibration(motor);

③ ERROR_MOTOR_STALL (code 24) + 3秒 stall 守卫
Hall 模式下，若电机被命令运动但 3 秒内无 Hall 脉冲（转速=0），触发 MOTOR_STALL 错误， 防止持续大电流堵转损伤 DRV8301 和电机绕组。 
// low_level.h – Error_t 枚举新增
ERROR_MOTOR_STALL, // 24 – Hall 电机堵转超过 3 s

// low_level.c – control_motor_loop stall watchdog
if (hall_stall_cnt[midx] > (uint32_t)(3.0f * current_meas_hz)) {
    motor->error = ERROR_MOTOR_STALL;
    break;
}
